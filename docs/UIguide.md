# MorphOpt UI 使用指南（定义 + 观察，单窗口）

MorphOpt UI 是一个 PySide6 图形界面，把“定义优化问题”与“观察/运行优化”放在**同一个窗口**的两个页面中。界面不另起观察器进程；代码/命令行发起的优化一律**无界面（headless）**运行，结果由 UI 通过磁盘轮询实时展示。

## 0. 启动

```bash
# 已 pip install morphopt 后，可直接用控制台命令启动：
morphopt-ui

# 源码目录 / 未注册命令时，也可用模块方式：
python -m morphopt.ui
```

- 首次启动直接进入完整的**优化定义工作台**。几何、载荷、工况、材料、目标、求解器和更新器栏目均已显示，但不预置具体定义；可从头编辑，或点击顶部 Quickstart 生成问题。
- Linux 需可用的 X 显示（Qt/pyvista 需要）。

## 1. 优化定义

顶部动作行（均为“定义页”内操作）：

| 按钮 | 作用 |
|---|---|
| 快速开始 · Quickstart | 选择形状优化或拓扑优化，设置初始结构、目标和工作条件，生成新的可编辑模型 |
| 打开 .morph | 载入已有 `.morph` 定义（文件自带 `scheme`，自动识别问题类型） |
| 导出 .morph | 把当前定义保存为 `.morph`（无损交换格式） |
| 导出运行 .py | 由当前定义生成一份可独立运行的无界面脚本 |

### 快速开始

点击 **快速开始 · Quickstart**，按五个部分创建模型：

1. **选择设计任务**：形状优化或拓扑优化。
2. **单独定义几何**：形状优化逐层填写层长、并联气腔数量、截面排布、半径、初始形状、相位和压力通道；拓扑优化填写设计域长、高、厚。
3. **定义多目标函数**：添加 1–8 个目标项，分别选择目标类型、权重和目标值，并为每项设置自己的载荷工况。形状优化的普通目标输入各压力通道的压力；拓扑优化目标输入末端载荷。工作空间目标不指定单点载荷工况，而是选择驱动通道、最大压力和边界高斯点数。
4. **设置材料参数**：剪切模量和体积模量单独放在材料参数区。
5. **设置输出**：任务名称、结果目录和拓扑材料占比。

右侧以正等轴测投影和 XYZ 坐标轴显示几何，并列出各目标权重及对应工况。壁厚不足、气腔重叠或工作空间可用独立压力通道不足时，
界面显示调整提示并禁用生成按钮。网格尺寸与几何尺寸放在同一几何区；形状优化默认同时优化内腔和外轮廓。初始气腔使用内核已有的圆柱面或球面。点击 **生成并编辑** 后，模型仍可在完整编辑器里修改、保存或导出。
Quickstart 会创建新模型；再次进入时恢复上次保存的 Quickstart 参数，不反向推断完整编辑器中的修改。

初始设计以气腔层为准：层沿 Z 轴从底部到末端串联，同层气腔并联；各层支持
增加、删除和上下移动。每层设置圆柱或球形初始气腔、周向或并排的截面排布。
总长度为各层层长之和，界面只读显示。气腔之间及内外边界的距离按最小壁厚检查。
压力通道以逗号分隔，每个气腔指定一个正整数；相同通道号共用压力，不同通道号独立作动。
通道可跨层复用，或为不同层单独分配。不再按气腔索引隐式分组。

目标支持弯曲、伸长、扭转、接触力，以及平面位置、空间位置、旋转和平面位姿工作空间。最终目标为各目标项损失乘权重后的加权和。
每个工作空间项需选择与其自由度数相同的独立压力通道。可从气腔压力通道中指定参与积分的输入；同一通道下的气腔作为一组联动，未选通道在该工作空间的积分工况中固定为零压。

工作空间按论文中的散度定理，在压力驱动域边界上积分。二维位置工作空间沿四条边求积：

$$
|W_{2D}| = \frac{1}{2}\oint_{\partial P}
\left(U_2 J_{t,1} - U_1 J_{t,2}\right)\,dt.
$$

三维位置和耦合位姿工作空间沿六个面求积：

$$
|W_{3D}| = \frac{1}{3}\int_{\partial P}
\mathbf{U}\cdot(\mathbf{J}_{t_1}\times\mathbf{J}_{t_2})\,dA.
$$

三维姿态工作空间使用指数坐标体积及论文中的 $1/24$ 系数。所选驱动压力域为
$[0,p_{\max}]^d$，未选通道固定为零压；每个边界积分工况将一个所选驱动压力固定在上下限，其他所选压力坐标用
Gauss–Legendre 点求积。因此 $n$ 表示每条边或每个面内自由坐标方向的高斯点数：
二维生成 $4n$ 个边界工况，三维生成 $6n^2$ 个边界工况。默认 $n=3$ 时分别为 12 和
54 个。积分权重按压力区间缩放，边界方向和面法向按散度定理取向。每个普通目标项单独指定压力或末端载荷工况；重复工况会合并求解。边界积分工况由所选工作空间驱动自动生成。

拓扑优化直接生成指定尺寸的二次六面体网格和 SIMP 密度场，支持承载刚度或目标末端
挠度，并自动设置材料占比约束。无需准备或选择外部网格模板。

中间主区（Abaqus 风格）：
- **左：模型树** —— 初始构型几何 / 载荷（载荷定义、载荷工况）/ 材料 / 求解器 / 优化问题定义；优化问题定义下并列显示优化目标、几何优化器和材料优化器（如有），几何优化器下可进入子优化目标、几何对称约束和罚函数约束。
- **中：编辑页** 与只读生成的代码（每次修改自动刷新）；辅助代码在编辑页中编写。
- **右：预览** —— 初始几何与各工况载荷。

编辑要点：
- **几何（多 Part 多实例）**：这里定义优化的**初始构型**；`几何` 下是一个个 **Part 接口**，每个 Part 接口下再列它自己的表面（只有边界 Part 才有表面）。右键 `几何` 可添加：边界曲面 Part（`BoundaryPartInterface`，可优化）、INP Part（`INPPartInterface`）、torchfea 模型 Part（`TorchFEAPartInterface`）。
  - **Part 名**默认就是接口注册名（在节点上编辑），不再固定为 `final_model`。
  - **Instance、BoundaryPart 曲面和 CAD 特征**都在所属 Part 编辑页中逐项展开参数，可以直接编辑，无需选中模型树中的子节点。Instance 名称、平移和旋转均可修改；不填名称时按 Abaqus 习惯自动生成 `<part>-1, <part>-2, …`，模型树会显示实际实例名（`[part=body, 实体=body-1]`）。一个 Part 可以有多个实例，载荷/材料按实例名引用。
  - 约定 **表面 0 = 外表面，≥1 = 内腔**；表面编号在每个 Part 内从 0 开始，全局顺序 = Part 顺序 + 各自表面顺序。
  - “几何对称约束”可通过编辑页或模型树右键添加、删除和排序。BSP 支持 xz / xy 镜面对称；CPGEO 支持镜面对称、旋转对称；BSP 和 CPGEO 也支持同类曲面间的刚体关系，位姿格式为 `[tx, ty, tz, rx, ry, rz]`。自定义项生成 Part 级 `apply_surface_constraints` 函数体。内置约束自动挂到曲面并在更新、重建时执行；约束列表顺序决定执行顺序。“几何罚函数约束”单独管理 Fairness、Distance 等罚函数项。
- **载荷**：左树的 `载荷` 下分为 `载荷定义` 和 `载荷工况`；在 `载荷定义` 下右键添加/删除/排序，点选后按类型编辑参数与名称；**改名会自动级联**到工况矩阵与 `jacobian_needed`。
- **目标函数**：`objective_function(self)` / `get_metrics(self)` 函数体（可手写代码，导出后编辑再粘回更稳妥）。
- **刚度/Jacobian 模板**：不会自动添加集中力或集中力矩；用户需先在 `载荷定义` 中添加它们，并让两者与模板选择的参考点一致。
- **求解器**：进程数、GPU、`task_index_list`（把某些载荷工况分到同一进程顺序求解）。
- **优化问题定义**：点击大类只显示概览；几何/材料优化器节点编辑最大迭代次数和更新开关；几何对称约束、罚函数约束可添加多个项目；子优化目标节点只显示各自内容。所有子优化器行为一致：各自指向一个更新对象（Part 或材料接口），互不干扰。
- **多个几何优化器（每个边界 Part 一个）**：在 `优化问题定义 → 几何优化器` 上右键“添加几何优化器”，会自动分配到尚未占用边界 Part；编辑器顶部用**目标 Part** 下拉框可改绑的 Part。模型树会显示 `几何优化器 · Part body` / `· Part leg` 两个并列节点，各自有自己的子优化目标、几何对称约束、罚函数约束，以及各自的曲面更新开关（只覆盖本 Part 的曲面）。
  - 每个 Part 的设计变量在梯度中按 Part 切片，状态分开保存到 `log/geometryupdater/<part_name>/`，互不干扰。
  - 目标 Part 必须是边界 Part（INP / torchfea Part 没有曲面）；未选或重复选会在生成代码时直接报错并列出可选项。
- **多个材料优化器（每个可设计材料接口一个）**：在 `优化问题定义` 上右键“添加材料优化器”，会自动分配到尚未占用、且带设计变量（SIMP 密度场）的材料接口；编辑器顶部用**目标材料接口** 下拉框可改绑。模型树显示 `材料优化器 · 材料 solid` / `· 材料 shell_mat`，各自有自己的子优化目标和罚函数约束。
  - 每个材料接口的设计变量在材料梯度中按接口切片，状态分开保存到 `log/materialupdater/<interface_name>/`。
  - 目标必须是有设计变量的材料接口（`HomogeneousMaterial` 无变量）；未选或重复选会在生成代码时直接报错并列出可选项。
  - 导出的脚本用一个 `define_updater()` 声明全部子优化器，按分类调用
    `add_geometry_updater(self.UpdaterBoundaryPart(), name='body')` /
    `add_material_updater(self.UpdaterSIMPMaterial(), name='solid')`；
    名字省略时按 `<类名>_<序号>` 自动命名；这个 `name` 同时也是该对象拥有的 interface
    （Part 名 / 材料接口名），updater 类本身不写目标，所以同一个类可以注册多次、分别优化不同 Part。

页脚：
- **`▶ 进入优化器`** —— 把当前定义交给观察页；在观察页点击 0 选择任务来源（当前定义 / 已有 .py / 已有结果续跑）后开始。

### 自定义类与方法重写（进阶）

模型树下方是 **自定义类（进阶）**，中间的分割栏可以拖动调整高度。

左侧模型树的 **辅助代码** 位于 **控制器** 前面，下面依次是 **自由代码块**、**辅助变量** 和 **辅助函数**。自由代码块可写完整的脚本级 Python 代码和 `import`。辅助变量逐项填写名称和 Python 值表达式，例如名称 `target_force`、值 `3.0`；辅助函数逐项填写名称、输入形参和函数体。变量和函数可通过分组的“添加”按钮或右键菜单新增，通过条目的“删除此项”按钮或右键菜单删除。后续参数输入框直接填写辅助变量名时，生成脚本会引用该变量，不会将名称当作字符串。辅助代码出现在生成脚本的导入语句之后、所有自定义类及 `ThisController` 之前，并随 `.morph` 保存。语法错误会显示在编辑页，并阻止运行或导出无效脚本。从只读代码页选中模型树节点时，界面会自动返回编辑页。

1. 点击下方的 **+**（或右键 → 添加自定义类），输入 Python 类名，选择框架父类，例如 `morphopt.Solver`。自定义类生成在脚本最外层；同一父类可以定义多个自定义类。
2. 选中自定义类，点击 **重写方法…**，从下拉框选择方法。列表包含父类及其继承的方法，包括 `__init__`、实例方法、类方法和静态方法。
3. 在代码编辑器中填写方法体。方法签名自动沿用框架父类；初始代码调用父类方法，可在它前后添加自己的逻辑。签名的提示信息显示父类文档。
4. **根级配置**：模型树以 Controller 为根；Params 是几何、载荷、材料的父节点，Solver 和 Updater 是 Controller 的其他子节点。选中 Controller、Params 或几何、载荷、材料、求解器、Updater，在编辑页顶部使用 **使用类** 下拉框。这里只列出兼容的类；**默认**恢复框架类。
5. **接口和目标函数**：右键对应父节点，在“添加几何接口 / 添加载荷 / 添加材料接口 / 添加曲面”菜单的 **自定义类** 子菜单中选择。优化目标通过 Updater 的“添加/替换优化目标 → 自定义类”选择。子优化目标和罚函数约束通过各自添加列表中的“自定义类”条目添加；继承具体类型的类沿用其参数表单，继承 BaseObjective / BaseConstraints 的类以自己的构造器默认值创建。
6. 通过左侧自定义类树中的方法节点切换编辑；**删除重写**恢复父类方法。右键自定义类 → **删除**，引用它的节点恢复默认选择。类改名时，节点选择也会同步更新。

例如创建 `CustomSolver(morphopt.Solver)`，在求解器节点中选用它。生成代码如下：

```python
class CustomSolver(morphopt.Solver):
    def reinitialize(self, iteration):
        return super().reinitialize(iteration)

class ThisController(morphopt.Controller):
    class Solver(CustomSolver):
        def __init__(self, params: Any) -> None:
            super().__init__(params=params, num_process=1)
```

自定义类提供行为，模型中的生成类传入 UI 参数。`super()` 调用框架父类；重写 `__init__` 时仍会收到 UI 配置的参数。如果重写 `define_interface`、`define_surfaces`、`define_instance`、`define_steps`、`define_objective` 等声明方法，该方法会替代对应的 UI 自动生成方法，请在方法体中写完整声明。

接口、曲面、目标函数和约束的自定义类保存到新建条目中，只影响该条目。树标签显示所用的自定义类名称。`.morph` 的 `custom_classes` 保存类和方法源码，`class_bindings` 保存根级配置选择，条目的 `custom_class` 保存其所用类；代码页、导出 `.py` 和 UI 发起的运行都会使用这些选择。只读取当前格式，不转换旧路径或隐式类选择。删除 Part 或子优化器后，应检查对应的类选择。

模型树条目统一显示为 **名称 [类名]**，例如 `finger [CustomGripperPart]`、`Root [BoundaryConditionInterface]`、`body [CustomBodyMaterial]`。选用自定义类时显示其实际名称。Part 的实例位置和旋转可在 Part 编辑页直接修改；实例列表及材料关联信息也可通过悬停查看。`BasePartInterface` 本身没有建模实现，只能通过“添加几何接口 → 自定义类”添加继承它的已定义类，不出现在普通几何类型菜单中。

## 2. 优化器

顶栏三个按钮：

| 按钮 | 行为 |
|---|---|
| 0 · 选择任务来源… | 三个来源任选：① 从当前定义优化（全新）② 从已有定义脚本 (.py) 优化（全新）③ 从已有结果目录续跑（可最后/指定步）。选中后顶行提示“当前任务：…” |
| 1 · 开始优化 / 继续优化 | 需先经 0 选择来源才可点击；运行开始后来源自动重置为“未选择”，因此停止/结束后需再次点击 0 选择才能运行 |
| 2 · 停止优化 | 终止当前任务（整个进程组），**保留当前可视化**；续跑需再次点击 0 选择该结果目录 |

内容区：
- 顶部**迭代滑杆**（可回看各步；勾选“自动跟踪最新”则随运行前进）。
- 左侧选项：**优化指标**（历史表 + 目标曲线）、**几何展示**（该步形状）、**工况 k**（该步该载荷工况的变形）。
- 右下：**`◀ 返回定义`** —— 回到定义页修改参数；若优化仍在运行会先弹窗确认（确认即终止该任务）。

## 3. 结果目录与文件约定

每次从 UI 发起（或命令行无界面）运行，控制器在结果根目录生成：

```
<run_root>/<label>_T<yyyymmdd_HHMMSS>/
├── log/                    # history_record.csv、deformation/task_<k>_iter_<n>.stl、geometry/*.npz…
│   └── geometryupdater/    # 每个几何优化器一个子目录：<part_name>/step_length_<iter>.npz
├── fea/                    # 网格/装配缓存
├── cache/
└── scripts/
    ├── MAIN_SCRIPT_FOR_RESTART.py      # 可运行/可续跑的规范脚本（框架写入）
    └── MAIN_SCRIPT_FOR_RESTART.morph   # 本次优化定义（由 UI 发起时自动写入）
```

- **`.morph`**：第 3 版 JSON 格式，顶层含 `scheme/label/result_folder/device/restart_per_iteration/root/custom_classes/class_bindings/helper_code/helper_variables/helper_functions`（root 为参数树，custom_classes 保存自定义类和方法体，class_bindings 保存类选择，helper_code 保存自由代码块，helper_variables 和 helper_functions 保存结构化条目）。可直接被 UI“打开 .morph”载入继续编辑、再“导出运行 .py”运行。
- 由 UI 发起的运行，会在结果目录 `scripts/` 里与 `MAIN_SCRIPT_FOR_RESTART.py` 并列保存一份 `MAIN_SCRIPT_FOR_RESTART.morph`，便于事后复现/继续。
- 代码/命令行运行**不再显示任何 UI 窗口**：生成脚本 `__main__` 调用
  `morphopt.start_optimization(device=…, restart_per_iteration=…)`，headless 执行。

## 4. 运行与调试提示

- **停止**：UI 向整个进程组发送 `SIGTERM`（超时后 `SIGKILL`）。每完成一步结果即已写盘，停止后可用“打开结果”继续。
- **从头重跑**：回定义页修改后再次“进入优化器”（会重置为从头运行）。
- 启动所需的最小模块文件位于**系统临时目录**（多进程 `spawn` 需要 import），不会写入工程目录。
- 若需要按旧脚本方式手写任务，见 `docs/module_definition_guide.md`（不经过 UI）。
