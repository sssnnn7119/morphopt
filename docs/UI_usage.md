# MorphOpt UI 使用指南（定义 + 观察，单窗口）

MorphOpt UI 是一个 PySide6 图形界面，把“定义优化问题”与“观察/运行优化”放在**同一个窗口**的两个页面中。界面不另起观察器进程；代码/命令行发起的优化一律**无界面（headless）**运行，结果由 UI 通过磁盘轮询实时展示。

## 0. 启动

```bash
# 已 pip install morphopt 后，可直接用控制台命令启动：
morphopt-ui

# 源码目录 / 未注册命令时，也可用模块方式：
python -m morphopt.ui
```

- 首次启动直接进入**优化定义**，默认载入 `shapeopt`（形状优化）示例。
- Linux 需可用的 X 显示（Qt/pyvista 需要）。

## 1. 优化定义

顶部动作行（均为“定义页”内操作）：

| 按钮 | 作用 |
|---|---|
| 更换优化问题 | 弹窗选择 形状优化 `shapeopt` / 拓扑·材料 `simp` / 协同设计 `codesign`，替换为对应默认定义 |
| 打开 .morph | 载入已有 `.morph` 定义（文件自带 `scheme`，自动识别问题类型） |
| 导出 .morph | 把当前定义保存为 `.morph`（无损交换格式） |
| 导出运行 .py | 由当前定义生成一份可独立运行的无界面脚本 |

中间主区（Abaqus 风格）：
- **左：模型树** —— 几何 / 载荷 / 工况 / 材料 / 目标函数 / 求解器 / 更新器。
- **中：编辑页** 与只读生成的代码（每次修改自动刷新）。
- **右：预览** —— 初始几何与各工况载荷。

编辑要点：
- **几何**：几何节点下右键添加/删除表面；约定 **表面 0 = 外表面，≥1 = 内腔**。代码槽 `apply_surface_constraints` / `_map_bsp_designfield` 可编辑函数体（建议：导出 `.py` 在 VS Code 中改好后再粘回）。
- **载荷**：左树 `Loads` 逐项列出，右键添加/删除/排序，点选后按类型编辑参数与名称；**改名会自动级联**到工况矩阵与 `jacobian_needed`。
- **目标函数**：`objective_function(self)` / `get_metrics(self)` 函数体（可手写代码，导出后编辑再粘回更稳妥）。
- **求解器**：进程数、GPU、`task_index_list`（把某些载荷工况分到同一进程顺序求解）。

页脚：
- **`▶ 进入优化器`** —— 把当前定义交给观察页；在观察页点击 0 选择任务来源（当前定义 / 已有 .py / 已有结果续跑）后开始。

## 2. 优化器

顶栏三个按钮：

| 按钮 | 行为 |
|---|---|
| 0 · 选择任务来源… | 三个来源任选：① 从当前定义优化（全新）② 从已有定义脚本 (.py) 优化（全新）③ 从已有结果目录续跑（可最后/指定步）。选中后顶行提示“当前任务：…” |
| 1 · 开始优化 / 继续优化 | 需先经 0 选择来源才可点击；运行开始后来源自动重置为“未选择”，因此停止/结束后需再次点击 0 选择才能运行 |
| 2 · 停止优化 | 终止当前任务（整个进程组），**保留当前可视化**；续跑需再次点击 0 选择该结果目录 |

内容区：
- 顶部**迭代滑杆**（可回看各步；勾选“自动跟踪最新”则随运行前进）。
- 左侧选项：**优化指标**（历史表 + 目标曲线）、**几何展示**（该步形状）、**工况 k**（该步该载荷工况的变形）。
- 右下：**`◀ 返回定义`** —— 回到定义页修改参数；若优化仍在运行会先弹窗确认（确认即终止该任务）。

## 3. 结果目录与文件约定

每次从 UI 发起（或命令行无界面）运行，控制器在结果根目录生成：

```
<run_root>/<label>_T<yyyymmdd_HHMMSS>/
├── log/                    # history_record.csv、deformation/task_<k>_iter_<n>.stl、geometry/*.npz…
├── fea/                    # 网格/装配缓存
├── cache/
└── scripts/
    ├── MAIN_SCRIPT_FOR_RESTART.py      # 可运行/可续跑的规范脚本（框架写入）
    └── MAIN_SCRIPT_FOR_RESTART.morph   # 本次优化定义（由 UI 发起时自动写入）
```

- **`.morph`**：JSON 无损格式，顶层含 `scheme/label/result_folder/device/restart_per_iteration/root`（root 为参数树，含各代码槽源码）。它知道自己属于哪种优化问题，可直接被 UI“打开 .morph”载入继续编辑、再“导出运行 .py”运行。
- 由 UI 发起的运行，会在结果目录 `scripts/` 里与 `MAIN_SCRIPT_FOR_RESTART.py` 并列保存一份 `MAIN_SCRIPT_FOR_RESTART.morph`，便于事后复现/继续。
- 代码/命令行运行**不再显示任何 UI 窗口**：生成脚本 `__main__` 调用
  `morphopt.start_optimization(device=…, restart_per_iteration=…)`，headless 执行。

## 4. 运行与调试提示

- **停止**：UI 向整个进程组发送 `SIGTERM`（超时后 `SIGKILL`）。每完成一步结果即已写盘，停止后可用“打开结果”继续。
- **从头重跑**：回定义页修改后再次“进入优化器”（会重置为从头运行）。
- 启动所需的最小模块文件位于**系统临时目录**（多进程 `spawn` 需要 import），不会写入工程目录。
- 若需要按旧脚本方式手写任务，见 `docs/module_definition_guide.md`（不经过 UI）。
